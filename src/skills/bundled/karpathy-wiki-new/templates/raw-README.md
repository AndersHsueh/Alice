# raw/

> **LLM 只读目录。本目录下任何文件禁止修改、禁止重命名、禁止删除。**

这里是知识库的**不可变源层**——一切事实的最终出处。wiki 里的每条结论都应该能顺着引用追回到这里的某个文件;
raw 一旦被改动,整个引用链就不再可信,这也是三层架构里唯一不允许 LLM 写的一层。

## 📥 放什么

领域无关,凡是"别人写的、你不打算再改的原始材料"都可以放:

- 文章、网页剪藏(`.md` / `.html`)
- 论文(`.pdf`,以及配套的文本版)
- 书籍章节、读书摘录(`.md` / `.txt`)
- 访谈、对话、播客的文字记录(`.md` / `.txt`)
- 会议记录与逐字稿(`.md` / `.txt`)
- 个人笔记与日志(`.md`)
- 数据表(`.csv` / `.xlsx` / `.json`)
- 图片:截图、照片、图表、手写稿扫描件(`.png` / `.jpg` / `.svg`)
- 邮件、聊天记录的导出(`.md` / `.txt`)
- 官方文档、说明书、规范原件(`.pdf` / `.md`)

## 🏷 命名约定

命名只有一个目标:**一眼看出这是什么、是什么时候的**。按素材形态挑一种即可,不必全库统一:

- 保留原标题(`一种新的记忆机制.md`)/ `<第一作者>-<年份>-<短标题>.md`(`Pan-2010-迁移学习综述.md`)
- 带时间的:`访谈-<对象>-<MMDD>.md`、`<会议名>-<MMDD>.md`、`日志-<YYYYMMDD>.md`
- 成批素材建子目录 `<来源>-<MMDD>/`;图片 `<主题>-<两位编号>.png`

## 🖼 剪藏与图片的处理建议

网页优先剪藏成 markdown(只存 URL 会失效)、图片一律下载到本地、PDF 留原件另存文本版、音视频转文字后入仓;带内联图的 markdown 要**两段式读取**(先读完文本,再按需逐张打开图片)。

## 🚫 LLM 行为约束

1. **只读** — 只用 Read / Grep / Glob 访问,**不要 Edit / Write** 本目录下任何文件
2. **发现问题只注 wiki** — raw 里有错别字、前后矛盾、信息不足、格式损坏时不改原文;在对应 wiki 主题页用 `> 待澄清:` 注记写明"`raw/X` 的 Y 处存在 Z 问题",需要人来拍板或分歧较大时,另建 `待澄清-<主题>.md` 页面记录
   > 四个注记标记(待澄清 / 矛盾 / 已过时 / 草稿)只有一份定义,见根目录 `CLAUDE.md`「时间戳纪律」附近的**注记标记表**,本文件不另作定义。
   > **源本身**有问题(错别字 / 自相矛盾 / 信息不足 / 需要人确认)一律用 `待澄清`,不要挪用其它标记
3. **新源入仓必走 Ingest 工作流** — 登记 log、判断影响范围、更新受影响的主题页与 `INDEX.md`。详见 `wiki/工作流-ingest-query-lint.md` 的 Ingest 一节
4. **保留原始组织结构** — 成批来源自带的子目录原样保留,不要为了整齐把文件散开、合并或改名
