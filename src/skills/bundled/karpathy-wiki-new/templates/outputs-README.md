# outputs/

> **LLM 可写目录。这里放从 `raw/` + `wiki/` 派生出来的成品。**

wiki 是知识本身,outputs 是知识的**一次性呈现**:为某个具体问题、某个具体读者、某个具体场合做出来的东西。
判断标准很简单——**删掉整个 outputs/ 不应该损失任何知识**,因为它随时能从 wiki 重新生成。
反过来,如果某个结论只写在成品里没落进 wiki,那它迟早会丢,应该先回填。

## 📤 放什么

| 形态 | 格式 | 说明 |
|------|------|------|
| markdown 报告 | `.md` | 针对一个问题的完整回答,句句带出处 |
| 对比表 | `.md` 表格 / `.csv` / `.xlsx` | 多个对象 × 多个维度的横向对比 |
| Marp 幻灯片 | `.md`(frontmatter 含 `marp: true`) | 可直接导出 PDF / HTML 的演示稿 |
| matplotlib 图表 | `.py` 脚本 + `.png` / `.svg` | 脚本与产出图一起留,图才可复现 |
| 数据文件 | `.csv` / `.json` | 从 wiki 抽取整理出的结构化数据 |
| 图片 | `.png` / `.svg` | 示意图、拼图、导出的截图 |

## 🏷 命名与目录

`<主题>-报告-<MMDD>.md` / `<对象A>-vs-<对象B>-对比.md` / `<主题>-slides.md`;图表配图放 `figures/`、数据放 `data/`、生成脚本放 `scripts/`(图与脚本同名)。

## ✅ LLM 行为约束

1. **生成必登 log** — 每产出一个正式成品,在 `wiki/log.md` 追加一条 `deliverable` 类型条目(`## [YYYY-MM-DD] deliverable | <产出物简述>`),写清为回答什么问题而做、依据哪些 wiki 页
2. **可被 wiki 反向引用** — 在相关 wiki 主题页加一段「## 关联输出」,写明"详见 `outputs/X`",让知识与成品双向可达
3. **引用写法推荐反引号加路径** — 从 wiki 里引用成品,**推荐**写成反引号加路径(`` `outputs/X` ``),一眼看出这是跨域引用而不是主题页互链;若写成 `[[outputs/X]]` 也**不算断链** —— lint 对含 `/` 的链接目标一律跳过。两种写法都合法,同一个库里保持一种即可
