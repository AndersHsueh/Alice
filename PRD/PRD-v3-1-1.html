ALICE / VERONICA v3.1.1

一次安静的扩张。四个 P2 issue —— 可观测性、多 Agent 协作、语音输入、插件市场 —— 在一个版本里收口。12 个 PR,565 条新断言,对 v3.1.0 公开接口零破坏性变更。

01执行摘要

这个版本是什么,以及它刻意不做什么。

v3.1.0 完成了基础弧线 —— P1 × 9,八项 Zod v4 运行时 Schema 校验、OpenTelemetry SDK 脚手架、LSP 集成、ripgrep 替换、karpathy wiki ingest / lint 内置 skill、token 预算条。v3.1.1 开启第二条弧线:在这些基础之上,把长期承诺的 P2 能力补齐,底下不做任何重写。

一句话

v3.1.1 让 ALICE 成为 可观测、可协作、可语音、可扩展 的助理 —— 不改变 v3.1.0 已经交付的内容。

v3.1.1 不做的事

  • 不引入新的运行时依赖。4 个 P2 能力都基于现有 import 表面构建:Voice 用 vm、crypto、child_process、events 等 Node 内置模块。
  • 没有破坏性 API 变更。每个 P2 入口都是可选的:teamMessageBus? 参数、voice_mode feature flag、按需实例化的 Marketplace 类、与 builtin tool 列表独立的 PluginRegistry。
  • 不引入远程基础设施。TeamMemorySync 远程端点、真正的 GPG / openpgp 签名验证、真正的 wake-word 模型(snowboy / openWakeWord)、插件市场 HTTP API —— 都是刻意留白的,留给 v3.2.0。

02四大能力

每个能力作为独立子系统交付 —— 可独立测试、可独立禁用、可独立替换。

I.

可观测性 · OTEL 本地 dashboard

基于 v3.1.0 的 OpenTelemetry SDK(issue #11),analytics 层读取 SDK 输出的 ~/.alice/otel/trace.jsonl console exporter,呈现一个隐私安全的本地 dashboard。聚合器是纯函数 —— 同样输入同样输出,无 IO,易测试。

隐私在聚合器出口强制。assertPrivacySafe 深度遍历输出对象,拒绝任何含 prompt、completion、system_prompt、user_message、assistant_message 子串的字符串值。聚合器只输出计数和类别名。

新增文件

  • src/services/analytics/analyticsRenderer.ts · ANSI / plain
输出
  • 7 天 × 24 小时调用密度热力图
  • 每日 input / output / total token 表
  • 每个工具的 call / success / failed / errorRate
  • 日期范围、totalSpans、skippedLines 计数

II.

协作 · 多 Agent 团队

最初的 v3.0.1 Coordinator 是单 Agent 串行器。v3.1.1 把它扩展为真正的团队:worker 共享一个 TeamMessageBus、可以发布与确认类型化消息、运行在 per-workspace 严格锁下避免相互覆盖。

5 个 PR 分层构建 —— 协议、tool 绑定、profile 表层、runner 集成、workspace 协调 —— 每一层独立测试。端到端契约在单个 24 断言的测试里验证:3 个 worker 并发跑同一 bus。

III.

输入 · 语音

4 个 PR 把语音子系统作为干净抽象落地:一个 VoiceProcessor 基类,两个实现(NullVoiceProcessor 走默认关闭路径,RealVoiceProcessor 走生产栈)、一个 WhisperCppEngine 通过子进程跑 whisper.cpp、一个 prototype EnergyWakeWordDetector 基于 RMS 能量。整个子系统只受一个 feature flag 控制:voice_mode。

架构契约是单一的 processUserInput(buffer) 入口。无论 buffer 是 { kind: 'text', content } 还是 { kind: 'voice', audio },函数返回相同的 NormalizedInput 形态。下游代码不需要知道。

05迁移与兼容性

v3.1.1 是严格的加性版本。v3.1.0 的所有消费方应无需代码改动即可升级。

升级步骤

无新增依赖、无破坏性 API 变更、无数据库迁移。发版 commit 在 main 上为 b71ed55,tag 为 v3.1.1。

行为变化(你可能注意到的)

  • profile 列表变 4 个 spawnable。:agents slash 命令会列出 consultant、researcher、executor、reviewer 而不是两个。如果有 UI 枚举该集合,数量会增加。
  • Runner 调用零侵入兼容。如果不传 teamMessageBus 给 runAgents(),行为与 v3.1.0 字节级一致。
  • 语音默认 flag 关闭。除非用户在 ~/.alice/settings.jsonc 显式加入 voice_mode: true,否则任何 voice 代码都不运行(NullVoiceProcessor)。
  • Plugin 系统在不显式实例化时静默。PluginRegistry、PluginSandbox、Marketplace 没有被任何现有调用点 import,直到你实例化一个之前都不会执行。

如果只有 10 分钟,先读这些

  1. release-notes/v3.1.1.md —— 可执行摘要
  2. test-list.md —— 27 个脚本验证什么的索引
  3. 本文档 02 章节的四个 cap 块

08v3.2.0 路线图

下一批的边界由 v3.1.1 明确留白的内容定义。

v3.2.0 具体候选清单

  1. 流式 OTEL dashboard。通过 fs.watch 监视 trace.jsonl,渲染增量而非全量重读。
  2. 真 wake-word 模型。把 EnergyWakeWordDetector 换成 SnowboyWakeWordDetector / OpenWakeWordDetector,加载模型文件。WakeWordDetector 接口不需要变。
  3. 真 GPG 签名验证。用 openpgp 或 gpg 子进程替换 HMAC 层。verifySignature 签名不变,底层实现换。
  4. Plugin 市场 HTTP API。新增 MarketplaceClient 类,从 URL 拉 manifest,对 pin 过的公钥验证签名,然后跑现有的 Marketplace.install 路径。
  5. 跨 OS 音频采集。AVFoundationCapture(macOS)、WASAPICapture(Windows)、PulseAudioCapture(Linux)。v3.1.1 的 AudioCapture 接口就是它们要实现的。
  6. Profile #3 —— writer。复用 executor 的 LLM 规划器形态,针对散文而非代码步骤调优。

这些都不会改变 v3.1.1 表面。它们是扩展。

09收尾

给下个维护者。

v3.1.1 故意做小。四个特性,每个都在自己的 flag 后面交付,每个独立可测,每个都留有明确的"下一步占位"。代码库大约增加了 15 个源文件 + 4,000 行测试代码;其他没动。

如果在调试某个子系统,最快的路径是:test-list.md → 对应的 test-issue-NNN.ts → 用 bun 跑。测试不是带 mock 的单元测试;它们构造真实的 TeamMessageBus、真实的 vm 沙箱、whisper.cpp 的真实 child_process stub、registry scan 的真实 fs 写。行为即行为。

如果在扩展某个子系统:接口(VoiceProcessor、PluginLoader、Marketplace、WorkspaceCoordinator)是故意做小的。读源码,而不是文档。

经验法则

交付最小、最诚实的东西。然后下一个最小、最诚实的东西。然后停。
