### 1.2 重大架构变更

- **Zod v4 升级**:`package.json` zod `^3.23.8` → `^4`(实际 `zod@4.4.3`)。仓库内 7 处既有 `import { z } from 'zod'` 全部走 v3 默认入口(zod v4 包仍提供 v3 兼容);新代码全部走 `import { z } from 'zod/v4'` 拿到 v4 API。2 处(v4 `required_error` + `invalid_type_error` 合并为 `error`)做了 v4 API 适配。
- **OpenTelemetry 三件套**:`src/observability/{otelSDK, otlpConfig, spans}.ts`。**零 OTEL 全家桶依赖** —— 只硬引 `@opentelemetry/api ^1.9.1`(平台无关 ~50KB),SDK 与 exporter 全部自研,覆盖 `ExportTraceServiceRequest` 最小子集。
- **7 个 AgentProfile 框架**:`src/runtime/agent/coordinator/{agentProfile, profileRegistry, spawn}.ts` + `concurrentAgentRunner.ts` + `slashHandler.ts`。2 个可 spawn(consultant / researcher),5 个明确"未实装"(coder / writer / reviewer / security / tester)。
- **LSP 集成**:`src/services/lsp/{stdioRunner, serverProcess, client, locationFormat, index}.ts` + 3 个 builtin 工具(lspGotoDefinition / lspFindReferences / lspDocumentSymbol),stub server 在 `test-case/fixtures/lsp-stub-server.mjs`。
- **TeamMemorySync 协议 v1**:push/pull envelope(`teamId + memory payload + version`),本地 mock 落 `~/.alice/team-sync/staging/<teamId>.jsonl`,24h 滚动 TTL,失败 warn-and-continue。远程 endpoint 已为 v4.0.0 RFC 预留。
- **Token Budget 接通 TUI**:`BudgetUsage` 类型 + `getUsage()` + `budget_update` 事件流 + `<TokenBudgetBar>` 挂 Footer。
- **ripgrep 替换 glob**:`src/utils/ripgrepRunner.ts` + searchFiles 优先 rg,降级 glob;`useRipgrep` / `useBuiltinRipgrep` 设置从死代码变活。
- **karpathy-wiki-ingest / lint bundled skills**:`src/skills/bundled/{karpathy-wiki-ingest, karpathy-wiki-lint}/` 两套独立 skill;BundledSkillLoader 自动发现为 `/karpathy-wiki-ingest` / `/karpathy-wiki-lint`。

### 1.3 工程治理

- **测试基线**:`test-case/` 目录统一所有 issue 测试脚本(`test-case/test-list.md` 索引),从 `src/scripts/` 迁入(2026-08-15 commit `a6adeae`)。
- **`testAllModels` 解耦**:`cliArgs.ts` / `extendedCommands.ts` 原直接 import `src/scripts/test-model.js` 的耦合已修,生产代码现在指向正式 `src/utils/testModel.ts`,`test-case/test-model.ts` 改为薄运行壳。
- **全量基线**:`for t in test-case/test-issue-0*.ts; do bun run "$t" || exit 1; done` → 168 + 440 = **608 PASS / 0 FAIL**。

## 四、已知问题与限制

- **gitee CLI `issue close` 报 HTTP 404**:本会话发现 `gitee issue close` 对本仓库所有 issue 返回 404(项目权限或 API 端点问题)。所有 6 个本会话需关闭的 issue 已由用户在 gitee 网页端手动关闭。
- **`src/shim/qwen-code-core.ts` 死代码层**:`canUseRipgrep()` 硬编码 `return false`、`getLastPromptTokenCount()` 硬编码 `return 0`,在 v3.0.1 已存在但未被消费。本次 #10 / #12 PR 实现了正常路径,但 shim 仍为死代码层 —— 计划在下个 release 清掉。
- **3 个 builtin tool 暴露风险**:`#20 wiki-ingest` 与 `#21 wiki-lint` 是 builtin skill(在 `~/.alice/skills/builtin/`),与 user skill(`~/.agents/skills/`)优先级冲突时 builtin 优先,用户不可覆盖。这是 v3.0.1 设计的安全护栏。
- **TeamMemorySync 远程 endpoint 未实装**:v3.1.0 仅协议 + 本地 mock;远程 endpoint(`POST /v1/teams/{teamId}/memories:push` + `GET :pull`)为 v4.0.0 预留。
- **5 个 AgentProfile 未实装**:`coder` / `writer` / `reviewer` / `security` / `tester` 在 v3.1.0 spawn 时会报明确"未实装"错误,框架已就位,实装等 v3.2.0 或后续。

### 5.2 行为差异

- **Zod v4 schema**:`required_error` + `invalid_type_error` 已合并为 `error`,自定义消息迁移参考 [Zod v4 docs](https://zod.dev/v4/changelog)。本仓库 6 处既有 zod 适配已完成,新代码可直接用 v4 API。
- **OpenTelemetry 默认关闭**:无配置变更时不启用,`obtainTracer()` 返 null 零开销。启用方法见 `src/observability/otlpConfig.ts`(读 `~/.alice/settings.jsonc` 的 `observability.otel` 段)。
- **Token Budget 状态栏**:v3.0.1 Footer 中 `ContextUsageDisplay` 仍读 `uiTelemetryService.getLastPromptTokenCount()`(硬编码 0),新 `<TokenBudgetBar>` 已在 Footer `rightItems` 占位,token 数据从 agentLoop `budget_update` 事件流接入。
- **searchFiles 性能**:在装有 `rg`(ripgrep)的系统上,默认走 `rg --files --glob`,性能 ~800ms → ~50ms(20k 文件级目录实测)。无 `rg` 自动降级回原 glob 行为,不报错。

### 5.3 新 API 速查

- `/consult` / `/research` slash 命令(对应 consultant / researcher profile spawn)
- `<TokenBudgetBar>` 状态栏组件
- `~/.alice/otel/trace.jsonl`(隐私过滤后的 span 日志)
- `~/.alice/team-sync/staging/<teamId>.jsonl`(本地 mock 协议 stage)
- `/karpathy-wiki-ingest` / `/karpathy-wiki-lint` bundled skill(`loadSkill` 触发)
